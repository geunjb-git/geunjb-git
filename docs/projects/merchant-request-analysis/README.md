# 점심 판매 준비 요청의 배정 대기와 완료 목표 분석

가상 수정 요청 100건으로 접수 → 배정 → 완료 시간을 나누고, 11시 완료 목표를 위한 운영 기준을 검토한 SQL 개인 프로젝트입니다.

## 핵심 결과

- 기존 데이터에서 11시 전 완료는 35/100건이었습니다.
- 처리 시간을 유지하고 배정 대기를 최대 20분으로 줄이면 45건, 최대 10분이면 59건, 즉시 배정하면 70건이 목표 내 완료로 계산됐습니다.
- 10시 30분 이전 접수 53건은 32건에서 51건으로 바뀌어 완료율이 60.4%에서 96.2%로 계산됐습니다.
- 추가 완료 24건 중 19건은 10시 30분 이전 접수였습니다.
- 30건은 접수 당시 남은 시간이 실제 처리 시간보다 짧았습니다.

## 운영 제안

9~10시 재고 점검 후 10시 30분 이전 판매 준비 요청 접수를 권장하고, 10분 이내 배정 목표를 시범 검토합니다. 이후 일반 요청은 접수 순서로 처리하고, 현재 주문에 영향을 주는 품절·가격 오류는 긴급 우선 배정 예외를 제안합니다. 긴급 예외의 효과는 후속 검증 대상입니다.

## 파일

- index.html — 그래프·상세 집계·SQL 11개·100건 탐색을 제공하는 웹페이지
- generate_data.py — 고정 seed의 Python 가상 데이터 생성기
- sample_merchant_requests_prelunch.csv — 분석 원본 100건
- schema.json — BigQuery 업로드용 스키마
- analysis.sql — 공통 CTE를 한 번 임시 테이블로 만든 뒤 조회문 11개를 실행하는 BigQuery 스크립트
- analysis_results.json — Python 재계산 결과와 요청별 계산값
- time_group_results.csv / scenario_results.csv — 스프레드시트 차트용 결과

## 재현

1. Python 3에서 `python generate_data.py`를 실행하면 같은 CSV를 재생성합니다. 외부 패키지가 필요하지 않습니다.
2. CSV를 BigQuery에 업로드합니다. 스키마는 schema.json, 건너뛸 헤더 행은 1로 설정합니다.
3. 테이블 경로는 `bonggeunj.merchant_ops_demo.merchant_requests_prelunch`입니다. 다른 환경에서는 analysis.sql의 경로 한 곳을 바꿉니다.
4. analysis.sql 전체를 실행하면 임시 테이블을 만들고 조회문을 순서대로 실행합니다. 웹페이지에서는 공통 CTE와 조회문 하나씩 복사할 수 있습니다.
5. index.html을 브라우저로 열거나 `python -m http.server 8000`으로 미리봅니다.

## 데이터 정의

기간은 한국시간 2026-11-02~06, 하루 20건입니다. 접수는 10:00~10:59, 배정 대기는 1~40분, 처리는 5~30분을 각각 정수 균등 추출합니다. 소요 시간 분포는 접수 시각·요청 유형에 공통으로 적용합니다. Seed는 20261111입니다.

`target_at`은 각 접수일의 11시, `snapshot_at`은 2026-11-06 18시입니다. 관찰 기준에는 모든 요청이 완료됐습니다. 목표 준수는 `completed_at <= target_at`으로 계산합니다. CSV의 시각에는 +09:00이 포함되며 한국시간 표시는 DATETIME(timestamp, 'Asia/Seoul')로 변환합니다.

## 해석 범위와 검증

수치는 가상 데이터에서 처리 시간을 고정하고 배정 대기를 변경한 계산값입니다. 인력·동시 처리·비용·배정 순서는 모델에 포함하지 않았습니다. 실제 도입 시 예상 처리 시간, 요청량, 담당자별 업무량과 긴급 예외의 영향을 함께 확인해야 합니다. 9시 출근·11시 판매 목표·10시 30분 권장 접수는 프로젝트에서 정한 운영 가정입니다.

ID 중복, 시각 선후관계, 생성 범위와 집계 합계를 확인했습니다. Python 재계산으로 사용자가 공유한 BigQuery 집계 35·45·59·70건, 지연 단계별 건수, 배정 여유별 30·12·17·41건, 추가 완료 24건을 대조했습니다. 최종 패키지의 SQL을 BigQuery에서 새로 실행한 검증은 별도입니다.

데이터 생성과 SQL 정리·웹 시각화는 ChatGPT·Codex와 협업했습니다. 사용자가 BigQuery에서 조회하고 해석·운영 시나리오를 논의했습니다.
