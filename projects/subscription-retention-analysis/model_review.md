# 원본 노트북의 모델 검토

`추가분석4`에서는 Random Forest와 Extra Trees로 갱신 여부를 분류하고 변수 중요도를 확인했다. 기존 코드에는 80:20 층화 분할, random_state=42, Random Forest 500개 트리가 있다. 원본의 모델 탐색 경험은 유지하되 아래 정의를 공개본에서 구분했다.

## 1. 분류 타깃이 다르다

원본 모델은 고객 마스터의 `renewed`를 사용했다. 이번 README의 퍼널은 `renewed_dec`, 즉 2022년 12월 갱신 여부다. 할인 코호트에서 두 플래그는 42명에게 서로 다른 값을 가진다. 기존 모델 점수를 12월 갱신 예측 성능이라고 옮겨 적을 수 없다.

## 2. 고객 중복과 상품 분류

원본 일부 탐색 표는 12월 상품 가격별로 고객을 결합해 13명이 두 행에 존재했다. 공개본은 797명 모두 한 행씩 존재하도록 분류했다. 고객을 임의로 `drop_duplicates`하면 어떤 상품 기록이 먼저 왔는지에 따라 그룹이 달라질 수 있으므로 연간권 기록 우선이라는 기준을 명시했다.

## 3. 행동 관찰과 결과의 시간 순서

원본의 난이도 수는 전체 시작 로그를 집계했다. 공개본은 첫 결제 후 30일로 제한했으며 155명의 값이 달라졌다.

또한 12월 갱신자 368명 중 91명은 첫 결제 후 30일 관찰 종료 이전에 갱신했다. 따라서 30일 전체 행동에는 갱신 후 기록이 포함될 수 있다. 이 자료는 회고적인 집단 비교에 사용하며, 미래 갱신을 예측할 때 이용 가능한 특징만으로 평가한 결과라고 주장하지 않는다.

## 4. 원본 모델 수치를 그대로 싣지 않은 이유

저장된 모델 출력과 현재 코드의 특징 목록도 일부 다르다. 예를 들어 Extra Trees 출력에는 현재 목록에서 주석 처리된 활동일수 비율이 남아 있다. 저장된 ROC-AUC나 변수 중요도를 현재 공개본의 검증 성과로 재사용하지 않았다.

공개본에는 실제 재계산한 고객 수·집계·행동 비교와 모델 검토를 포함했다. 원본 분류 모형을 새 타깃으로 재학습한 성과를 추가하지 않았다.

## 운영용 예측으로 확장하려면

예측 시점을 먼저 정하고 그때까지의 로그만 특징으로 사용해야 한다. 예를 들어 결제 후 7일 시점에 아직 갱신하지 않은 고객을 대상으로 이후 일정 기간의 갱신을 정의할 수 있다. 이후 고객별 중복을 막고 가입 시점에 따른 검증, 클래스 비율, ROC-AUC·PR-AUC 및 실제 CRM 실험을 검토한다.

변수 중요도와 행동 차이는 인과효과를 의미하지 않는다. 안내 대상·콘텐츠 추천에 활용하는 것은 가설이며, 실제 효과는 무작위 비교 실험으로 확인해야 한다.
